# T09 register_artifact.py: one artifact registration tool game repositories can call (#23, ADR-009)

- **Kind**: infrastructure
- **Issue**: #23 · **Branch**: `task/T09-register-artifact` · **Merge after**: T07
- **Implementer**: opencode (`deepseek-flash`): **hard** (rule 20: a guard task, artifact identity,
  and a new mechanism that several repositories call) · **Claude fallback**: opus. **Round 3: claude
  (opus)**, escalated by the owner on 2026-10-04. Rounds 1 and 2 each had two blocking findings,
  and round 2's R1 (absolute or escaping paths accepted) is the same class as round 1's R1 (a forged
  id accepted): input that `check` and `validate` accept without validating it
- **Reviewer**: opencode, `review.mjs --hard --sol` (GPT-6.1 Sol at low effort first); never the
  implementer's family. **Guard task**: this tool computes the id that every run record, finding and
  evidence manifest names (ADR-006). A wrong id or a wrongly accepted copy corrupts evidence
  identity in every game repository.
- **Why**: ADR-009 moves code here when a second consumer copies it. Three repositories carry a
  `tools/register_artifact.py`. T07's migration issues (toy-archaeology#14, goal2-archaeology#22,
  isle-wars-archaeology#42) will pin `tools/validate_records.py`. Registration belongs beside it, so
  that they do not keep three copies of the identity rule's callers.
- **Evidence** (re-checked 2026-10-04):
  - **toy-archaeology and goal2-archaeology** (84 and 87 lines, near-identical: goal2 adapted toy's
    at a3056ff):
    - CLI: `register_artifact.py <dir> --label --title --version --how [--when, default today]
      [--note] [--writes GLOB]…`.
    - It prints the manifest of every file under `<dir>`, computing the id with the pinned checker's
      `canonical_set_hash` (through `tools/ga.py`).
    - `--writes` globs are recorded in `runtime_writes`, but matching files stay in `files`.
  - **isle-wars-archaeology** (295 lines), with three subcommands:
    - `manifest <dir> --label --title --version --how --when [--note] [--runtime-write GLOB]…
      [--exclude GLOB]…`. Files matching a `runtime_writes` glob or an `--exclude` glob leave `files`,
      and `--exclude` is not recorded.
    - `check (<dir> | --list <file>) <set-id> [--strict]`. It re-hashes a copy, or reads
      `<sha256>  <bytes>  <path>` lines, and compares them with the `artifacts/known.json` entry,
      skipping files that match `runtime_writes`. `unlisted: <path>` fails only with `--strict`.
    - `validate`: every `known.json` entry against the schema, with its id recomputed.
    - It imports a vendored copy of `check_examples.py` (isle-wars-archaeology#42 replaces it).
  - **U21** (`formats/README.md`): in a successor set, a shipped file the game writes moves from
    `files` to a `runtime_writes` glob. isle-wars' behaviour matches this. toy and goal2 keep matching
    files in `files`. That never mattered for them, because their registered globs match no shipped
    file.
  - **The ids reproduce today:**
    - toy-archaeology's tool, run on toy-target release `toy-isles-1.0-1.1` (`MANUAL.md` and
      `toy-isles-1.0.pyz`; label `toy-isles-1.0`; title and version from the release's
      `artifact-set-toy-1.0.json`; `--how generated --when 1970-01-01 --note "built by build.py"`;
      writes `*.sav` and `*.bin`), prints `toy-isles-1.0-60ef5d8c`, the registered id.
    - goal2's tool, run on its cached release, prints `goal2-a949da2f`.
  - Every set in the three repositories' `artifacts/known.json` (7 sets) validates with
    `tools/validate_records.validate_document`.
  - The file layout: the tool is fetched with `tools/validate_records.py` and
    `formats/*.schema.json` at a pinned commit, so it runs from a cache folder, not from the game
    repository it serves.
- **Owns**: `tools/register_artifact.py`, `tests/formats/**`, `formats/README.md`,
  `.github/workflows/ci.yml`
- **Scope**:
  - **Protects:** artifact identity in every game repository. None of these may get through:
    - a manifest whose id differs from what `canonical_set_hash` gives for the same files, or from
      a registered id for the same files and arguments;
    - a `check` that prints `ok` for a copy whose listed files differ in bytes or sha256, or are
      missing;
    - a file matching `runtime_writes` or `--exclude` left in `files`, or a shipped file the game
      writes counted as a mismatch after it moved to `runtime_writes` (U21);
    - a malformed `known.json` or listing that crashes the tool instead of giving a named error;
    - the identity rule re-implemented instead of imported from `tools/validate_records.py`;
    - a path in a manifest that is absolute or leaves `<dir>`.
  - **`tools/register_artifact.py`**, stdlib only, Python ≥ 3.11:
    - It imports `canonical_set_hash`, `validate_document` and the schema loading from
      `tools/validate_records.py`, found beside it (the same `tools/` and `formats/` layout as T07).
    - Its subcommands and behaviour follow isle-wars-archaeology's (the U21-consistent one):
      `manifest`, `check` and `validate`.
    - `--when` defaults to today; toy and goal2 rely on that.
    - The game repository's `known.json` is `--known PATH`, default `artifacts/known.json` relative to
      the working directory, never relative to the script.
    - `--writes` is accepted as an alias of `--runtime-write`, so toy's and goal2's calls keep working
      after `manifest` is added in front.
  - **Library functions** for the consumers' own tools and tests:
    - `build_manifest(directory, label, title, version, how, when, note=None, runtime_writes=(),
      excludes=())`;
    - `hash_tree(directory, manifest)`;
    - `read_listing(path)`;
    - `compare(observed, manifest, strict=False)`;
    - `known_errors(known)`.
  - **Output and exit codes:** errors are named lines on stdout and exit 1; usage errors exit 2. No
    traceback on any input, as in T07.
  - **`formats/README.md`:** in "The validator", how to fetch and call the tool, and that a
    successor set is registered with it (U21).
  - **CI:** one step runs the tool's tests.
  - **Not in scope:**
    - any change to `validate_records.py`, a schema or an example;
    - the game repositories' migration (filed in each repository when this merges);
    - `fetch_artifact.py` and the release-download logic;
    - any new identity rule.
- **Done when** (each runnable by a read-only reviewer):
  1. `python3 tests/formats/check_examples.py`, `python3 tests/formats/check_validator.py` and
     `python3 tools/check_links.py` exit 0.
  2. **A registered id reproduces from toy-target's public release:**
     `d=$(mktemp -d ./t09-XXXXXX) && gh release download toy-isles-1.0-1.1 -R diegoami/toy-target -D "$d" && mkdir "$d/set" && cp "$d/MANUAL.md" "$d/toy-isles-1.0.pyz" "$d/set/" && python3 tools/register_artifact.py manifest "$d/set" --label toy-isles-1.0 --title "$(python3 -c "import json,sys;print(json.load(open(sys.argv[1]))['title'])" "$d/artifact-set-toy-1.0.json")" --version 1.0 --how generated --when 1970-01-01 --note "built by build.py" --runtime-write '*.sav' --runtime-write '*.bin' | python3 -c "import json,sys;print(json.load(sys.stdin)['id'])"; rm -rf "$d"`
     prints `toy-isles-1.0-60ef5d8c`. The same with `--writes` in place of `--runtime-write` prints the
     same id.
  3. **Every registered set validates:** for each of toy-archaeology, goal2-archaeology and
     isle-wars-archaeology, fetch `artifacts/known.json` with
     `gh api repos/diegoami/<repo>/contents/artifacts/known.json --jq .content | base64 -d > <file>`
     (it holds hashes only, never game files). Then `python3 tools/register_artifact.py validate --known <file>`
     exits 0, and the three runs report 2, 1 and 4 sets.
  4. **`check` catches a changed copy:**
     - on the toy set from DW2, with a `known.json` built from the release's
       `artifact-set-toy-1.0.json` (`{"sets":[{"manifest":…}]}`), `check "$d/set" toy-isles-1.0-60ef5d8c --known <file>`
       exits 0 with `ok:`;
     - after one byte of `toy-isles-1.0.pyz` is changed, it exits 1 naming that file;
     - with the file deleted, it exits 1 with `missing`;
     - with an extra `x.sav`, it still exits 0 (`runtime_writes`);
     - with an extra `x.txt`, it prints `unlisted: x.txt`, exits 0, and exits 1 with `--strict`.
  5. **It runs as a consumer would fetch it:** a temporary `tools/` and `formats/` holding only
     `tools/validate_records.py`, `tools/register_artifact.py` and `formats/*.schema.json`, run from
     another working directory, gives DW2's id.
  6. **Tests prove behaviour:** the PR body shows the tool's tests failing, each naming its case, for
     each of these deletions in `tools/register_artifact.py`, and passing once restored with
     `git checkout -- tools/register_artifact.py`:
     - dropping the `runtime_writes` filter in `build_manifest`;
     - dropping the sha256 comparison in `compare`;
     - dropping the `--strict` failure.
  7. Bad input is an error, not a crash: a `known.json` that is not JSON, one without `sets`, a set
     id not in it, and a listing line with a non-integer size each exit 1 with a named line and no
     traceback.
  8. `grep -n 'def canonical_set_hash\|sha256(json' tools/register_artifact.py` prints nothing, so
     the identity rule is imported, not re-implemented. CI is green on the PR.
- **Hazards**:
  - Re-implementing the canonical hash, or serialising the manifest differently before hashing. Every
    id changes silently.
  - Reading `known.json` relative to the script. A fetched copy lives in a cache folder, not in the
    game repository.
  - Keeping toy's "matching files stay in `files`" behaviour. U21 says they leave it.
  - Downloading or writing game files inside the worktree. DW2 uses toy-target's public, generated
    release, and the temporary folder is removed.
