- **Scope**:
  - **Protects:** evidence and citation integrity in every game repository. None of these may get
    through:
    - `verify_evidence` printing `ok` for a bundle whose file differs in one byte, is missing from
      the release, or carries a wrong asset name;
    - a stale cached file accepted in place of this run's download;
    - a partial bulk download that passes, or fails without naming what is missing;
    - `check_citations` passing a finding that cites a run with no record, or an Answer or
      Inferences bullet that cites none on any of its lines;
    - a crash or traceback on any input instead of a named error;
    - the evidence-manifest rules re-implemented instead of imported from
      `tools/validate_records.py`.
  - **`tools/check_citations.py`**: goal2's version, moved. `--runs` defaults to `runs/` under the
    working directory, never relative to the script.
  - **The owner's decision of 2026-10-04 (U25):** in `## Answer` and `## Inferences`, a finding may hold
    only these lines:
    - list items (`-`, `*`, `+`, `1.` or `1)` markers) and their indented continuation lines;
    - `###` sub-headings;
    - table rows (lines starting with `|`), where every data row must cite a run id, as a bullet
      must, and the header row and the `|---|` separator are exempt;
    - blank lines.

    Every other line there is a named error, `<file>:<line>: unsupported in a protected section:
    <line>`: HTML of any kind, a blockquote line, a fence, any heading other than `###`, a setext
    underline, and a second `## Answer` or `## Inferences`. The section's own heading is exactly
    `## Answer` or `## Inferences`, and any other spelling of it (case, closing `#`s, tabs) is an
    error. This rule replaces, rather than extends, line-by-line parsing of other Markdown inside
    these sections. `formats/templates/finding.md` gains one sentence stating the rule.
  - **The owner's decisions of 2026-10-04 (U27, as revised by U28):** a heading is any line starting
    with `#` after any `>` quote and list-marker prefixes, a setext heading, or an HTML `<h1>`–`<h6>`
    line, anywhere in the file. Its **raw** text is entity-decoded (`html.unescape`), NFKC-normalised,
    casefolded and reduced to its letters (`str.isalpha`); nothing else is removed and no rendering
    is modelled. Two errors follow, both `<file>:<line>: unsupported in a protected section: <line>`:
    - the letters **contain** `answer` or `inferences`, and the line is not exactly `## Answer` or
      `## Inferences`;
    - the heading's letters come from more than one Unicode script (by `unicodedata.name`), as with
      look-alike letters (#28).
  - **U30 (owner, 2026-10-04), replacing U29:** HTML headings are banned in findings. Any line
    containing `<h1`–`<h6` (case-insensitive), anywhere in the file, is the error
    `<file>:<line>: unsupported in a protected section: <line>`. Nothing is parsed or matched across
    lines; U28's two rules still apply to Markdown and setext headings.
  - **U31 (owner, 2026-10-04):** any ATX or setext heading, anywhere in the file, whose text contains
    `<` or `[` is the same named error. Tags, links, images, autolinks and comments all start with
    one of them, so no markup can add letters that split a word past U28.
  - **Existing findings must keep passing.** The only failures allowed are a real missing citation,
    or the two known lead-in lines under U25, in goal2's F002 and F004, or goal2 F002's
    `### Inferences about the executable` under U28, or the strict readings the owner confirmed in
    U26: a list item's second paragraph (isle-wars F002:27 and F005:22) and `<...>` inside a code span
    (goal2 F001:17). goal2 F005, added after this task was written, fails under U25 and U28

    `check_citations.py` on every finding in toy-archaeology, goal2-archaeology and
    isle-wars-archaeology (`gh repo clone … -- --depth 1` into a temporary folder; findings and run
    records only, never game files). Report each result in the PR body; do not edit those
    repositories.

- **Hazards**:
  - **Per-asset downloads.** That is the slowness this task removes: toy-archaeology's E001 needs one
    call, not 477.
  - **A partial bulk download that passes.** Compare the downloaded names against the manifests'
    assets, retry what is missing, and name what is still missing.
  - **Accepting a cached file.** Download into a fresh directory every run.
  - **Paths relative to the script.** The fetched tools live in a cache folder, not in the game
    repository.
  - **Leaving toy-archaeology's clone or its 477 files in the worktree.** Remove the temporary folder.
