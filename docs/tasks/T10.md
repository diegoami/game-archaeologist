- **Reviewer**: opencode, `review.mjs --hard --sol` (GPT-6.1 Sol at low effort first); never the

  intact, and `check_citations` decides whether a finding's claims rest on recorded runs. A defect
  passes altered evidence or uncited claims as reviewed.
- **Why**: ADR-009 moves code here when a second consumer copies it. toy-archaeology and
  goal2-archaeology each carry both tools. goal2's T03 adapted them from toy's and fixed
  toy-archaeology#12. It fixed toy-archaeology#11 only in part, so the copies have diverged and toy's
  still carry both bugs.
- **Evidence** (re-checked 2026-10-04):
  - **goal2-archaeology `tools/check_citations.py`** (94 lines):
    - `<finding.md> [--runs DIR]`, with runs defaulting to the repository's `runs/`.
    - It fails when a run id (`E<nnn>-r<nnnn>`) anywhere in the finding has no
      `runs/E<nnn>/<id>.json`, or when a bullet under `## Answer` or `## Inferences` cites none.
    - Indented continuation lines belong to their bullet (toy-archaeology#12).
    - It has 15 tests in `tests/test_check_citations.py`, with fixtures in
      `tests/fixtures/citations/`.
  - **goal2-archaeology `tools/verify_evidence.py`** (142 lines):
    - `E<nnn> [--local DIR] [--evidence-dir DIR] [--repo OWNER/NAME]`.
    - It checks every entry of `evidence/E<nnn>/*.manifest.json`: the asset name
      `<sha256[:16]>-<name>` and the sha256 of the file in release `E<nnn>`.
    - It lists the release once, but **downloads each distinct asset in its own `gh` call**.
    - A failed or empty download is retried once and then reported by name, and a cached file is
      never accepted in place of this run's download.
    - It has 12 tests in `tests/test_verify_evidence.py`, with fixtures in
      `tests/fixtures/{evidence,evidence_bulk}/`, using a mock `gh`.
  - **Measured on toy-archaeology's real E001** (323 manifests, 477 distinct assets, 2026-10-04):
    - goal2's tool was still downloading one asset at a time after more than 10 minutes, and was
      stopped.
    - One `gh release download E001 -D <dir>` fetched all 477 in **31 s**.
    - `verify_evidence.py E001 --local <dir>` then printed `ok: 323 manifest(s) verified`.
    - `check_citations.py findings/F001-*.md` exited 0 on toy-archaeology's F001.
  - toy-archaeology#11 also saw one bulk download exit 1 with 476 of 477 files and no message, and
    a retry got all 477.
  - `tools/validate_records.py` (T07) holds the evidence-manifest rules, including the asset name.
  - Both tools hard-code `REPO_ROOT` from the script's path and a default repository. Once fetched
    into a cache folder, they serve the game repository in the working directory.
- **Owns**: `tools/verify_evidence.py`, `tools/check_citations.py`, `tests/tools/**`,
  `formats/README.md`, `.github/workflows/ci.yml`
- **Scope**:
  - **Protects:** evidence and citation integrity in every game repository. None of these may get
    through:
    - `verify_evidence` printing `ok` for a bundle whose file differs in one byte, is missing from
      the release, or carries a wrong asset name;
    - a stale cached file accepted in place of this run's download;
    - a partial bulk download that passes, or fails without naming what is missing;
    - `check_citations` passing a finding that cites a run with no record, or an Answer or
      Inferences bullet that cites none on any of its lines;
    - a crash or traceback on any input instead of a named error;
    - the evidence-manifest rules re-implemented instead of imported from
      `tools/validate_records.py`.
  - **`tools/check_citations.py`**: goal2's version, moved. `--runs` defaults to `runs/` under the
    working directory, never relative to the script.
  - **`tools/verify_evidence.py`**: goal2's version, moved, with these changes:
    - it downloads the release in **one** `gh release download E<nnn> -D <fresh dir>` call into a
      fresh directory, never into a cached one;
    - any listed asset that is missing afterwards gets one retry, by name, and is then reported by
      name;
    - the files are checked locally, as `--local` does;
    - each manifest is validated with `validate_records.validate_document` (schema, asset name),
      not with a re-implemented name rule;
    - `--evidence-dir` defaults to `evidence/` under the working directory;
    - `--repo` defaults to the working directory's GitHub repository (`gh repo view --json
      nameWithOwner`);
    - the cache is under the working directory's `.cache/evidence/`.
  - **Tests:** goal2's two test files and their fixtures move to `tests/tools/`. They are adapted to
    the bulk download (the mock `gh` counts calls). A new test shows that the number of `gh` calls
    does not grow with the number of manifests or assets. CI runs them.
  - **`formats/README.md`** (beside T07's and T09's sections): how a game repository fetches and
    runs them.
  - **Not in scope:**
    - any change to `validate_records.py`, `register_artifact.py`, a schema or an example;
    - the consumers' migration (filed in toy-archaeology and goal2-archaeology when this merges);
    - any new citation or evidence rule.

- **Hazards**:
  - **Per-asset downloads.** That is the slowness this task removes: toy-archaeology's E001 needs one
    call, not 477.
  - **A partial bulk download that passes.** Compare the downloaded names against the manifests'
    assets, retry what is missing, and name what is still missing.
  - **Accepting a cached file.** Download into a fresh directory every run.
  - **Paths relative to the script.** The fetched tools live in a cache folder, not in the game
    repository.
  - **Leaving toy-archaeology's clone or its 477 files in the worktree.** Remove the temporary folder.
