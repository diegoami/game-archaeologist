# T02 Formats and vocabularies v1 (A2)

- **Kind**: architecture
- **Issue**: #3 · **Branch**: `task/T02-formats-v1` · **Merge after**: T01
- **Implementer**: claude (opus, the main session) · **Reviewer**: opencode (`luna`), then a supplementary `deepseek-flash` review of any Done-when line the first review shows no evidence for (harness_imperial#19); never the implementer's family
- **Why**: the toy research repo (A5/Y1–Y3) and the Isle Wars repo (W3x onward) record runs,
  artifacts, evidence and findings in these shapes. The walking skeleton then tests them, and A6
  freezes them as `formats-v1`.
- **Evidence** (pasted; the accepted text is in `docs/phase0/`, and these are its binding parts):
  - 06 §2, the run record: `schema`, `run_id`, `experiment`, `arm`, `rep`, `code_commit`, `machine`,
    `artifact{set,variant}`, `runtime{driver,platform,fingerprint}`, `interventions[{level,what,variant}]`,
    `start_state{id,sha256,restore}`, `seed`, `actions{script,sha256,args}`,
    `observations[{step,source,field|addr,value|ref}]`, `outputs[{name,sha256,store}]`, `started`,
    `ended`, `status` (`completed | aborted: <reason>`). "No interpretation fields. A `decoded` view
    may be added **only** with `"via": "R014"` naming the representation claim."
  - 06 §3: interventions I0 pure observation, I1 passive instrumentation, I2 harness-enabling claimed
    neutral, I3 behaviour-altering. "Every run lists its interventions; a finding states its max level."
  - 06 §4: claim statuses `unknown`, `documented`, `hypothesis`, `supported`, `corroborated`,
    `refuted`, `contested`, plus the `superseded-by` link. `inconclusive` is a finding outcome.
    Basis: `doc`, `observed`, `parsed`, `static:decompile|listing|bytes`, `intervened`,
    `quantified: N of N`. Scope: artifact set (and variant), settings, state preconditions. A required
    `Confidence:` line, with no number. One correction style:
    `> **Correction (YYYY-MM-DD, F0nn):** …`.
  - 06 §5: representation claims `R<nnn>` in `spec/representation.md`.
  - 06 §9: `spec/README.md`, `spec/representation.md`, `spec/<area>.md`. An area holds a short prose
    summary of supported/corroborated claims, then the table `ID | Claim | Status | Scope | Basis | Findings`,
    e.g. `C-SET-01`.
  - 05 §2:
    - `artifact-set/1`: `id` embeds the first 8 hex of the canonical manifest's sha256 ("files
      sorted by path, without `acquired`"); `title`, `version`, `acquired{how,when,note}`,
      `files[{path,bytes,sha256}]`, `runtime_writes`.
    - `variant/1`: `id`, `base`, `replaces`, `recipe{script,commit,options}`, `output_sha256`,
      `interventions`.
  - 05 §4: bundles are release assets named `<sha256[:16]>-<name>`, one release per experiment. The
    manifests at `evidence/E<nnn>/<run-id>.manifest.json` are the index. Each evidence manifest names
    its set and variant.
  - 03 §2.2 (research extension) and §6.4 (tiers V0–V4).
  - 01 §3, §4, the IC2 failures these formats must prevent:
    - `results.json` kept 1 of 4 seeds;
    - a lossy per-type dict;
    - no build hash in results;
    - the seed build identified only by a truncated hash in prose;
    - interventions unstamped.
- **Owns**: `formats/**`, `vocabulary/**`, `tests/formats/**`, `.github/workflows/ci.yml` (one added step)
- **Scope**:
  - JSON Schemas `run/1`, `artifact-set/1`, `variant/1`, `evidence-manifest/1`, each with valid and
    invalid examples.
  - Markdown templates: finding, experiment README, spec area, spec representation.
  - Legends: `status.md`, `basis.md`, `interventions.md`, `tiers.md`.
  - `tests/formats/check_examples.py`, stdlib only. It:
    - validates the examples against the schemas, implementing only the JSON Schema keywords the
      schemas use and failing on any other;
    - checks the two rules a schema cannot express: the set id's hash suffix, and the asset name
      `<sha256[:16]>-<name>`;
    - checks that `status.md`'s statuses equal 06 §4's table.
  - **Not in scope**: a validator CLI for game repos (deferred, ADR-009); game-specific fields;
    a knowledge-map format (W0); a spec ontology.
- **Decisions**:
  - field names, and the required/optional split;
  - the canonical-manifest serialisation that the set id hashes;
  - the observation `source` values;
  - how an I0 run lists its interventions;
  - the claim-id patterns.
- **Escalate**: any field whose need is not traceable to the evidence above. Propose it; do not add it.
- **Done when**:
  1. `python3 -m json.tool` succeeds on every `.json` file under `formats/`.
  2. `python3 tests/formats/check_examples.py` exits 0. It reports every `valid/` example valid and
     every `invalid/` example invalid with its expected error, for each of the four schemas.
  3. Deleting `interventions` from `run/1`'s `required` makes `check_examples.py` exit 1, because
     `run-1--missing-interventions.json` then validates. The same holds for removing
     `additionalProperties: false` from `run/1`, because `run-1--interpretation-field.json` then
     validates.
  4. Changing one hex digit of the valid artifact-set example's id, or of an evidence-manifest asset
     name, makes `check_examples.py` exit 1.
  5. `grep -L "^## Legend" vocabulary/*.md` prints nothing. `check_examples.py` reports that
     `status.md`'s statuses equal 06 §4's table.
  6. `python3 tools/check_links.py` exits 0, and CI is green with the new step.
- **Hazards**:
  - inventing fields "for later" (ADR-009);
  - an interpretation field in `run/1`: the run record is raw only;
  - a validator that silently ignores an unknown keyword (it must fail);
  - drifting from the package wording (transcribe; escalate a gap).
